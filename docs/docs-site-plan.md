# Glass docs site plan

Date: 2026-10-10. Status: planning (glass-os-plan.md, Task 23). Decision 12: one site that people can read, agents can follow, and that also works as the marketing page.

## Where it lives

The site goes in a new public repo, `glass-os` (the `rom/` tree once Task 1 inits it). Its folder is `site/`, and it deploys to GitHub Pages. The glass-launcher repo keeps its README and links to the site. Why:

- The install tiers span the launcher, the Magisk module and the ROM, so they belong next to the build scripts.
- The launcher repo's hooks, board and e2e machinery stay untouched.

## Stack: Astro Starlight + `starlight-llms-txt`

- **Starlight** builds a static docs site from Markdown/MDX. It has search (Pagefind), sidebar, dark mode and i18n built in, with no server.
- **`starlight-llms-txt`** (0.11.x, needs Astro 7 / Starlight ≥ 0.41) generates `llms.txt`, `llms-full.txt` and `llms-small.txt` at build time from the same pages, so the agent layer cannot drift from the human docs. Sources:
  - https://github.com/trueberryless-org/awesome-starlight
  - https://app.unpkg.com/starlight-llms-txt@0.11.0/files/CHANGELOG.md
- **Rejected:**
  - **Material for MkDocs:** in maintenance mode since Nov 2025; its team moved to Zensical, which lacks plugin parity. Sources:
    - https://discuss.privacyguides.net/t/mkdocs-material-is-now-in-maintenance-mode/32736
    - https://pydevtools.com/handbook/reference/mkdocs-material/
  - **Docusaurus:** a heavier React app for a dozen pages.
  - **Hand-written HTML:** no search and no generated llms.txt.
- A custom `src/pages/index.astro` landing page gives the marketing face: a hero screenshot, a tier picker and a "what you keep" list.
- Pin versions in `package.json` and verify them with Context7 / the changelog when the site is built.

## Agent layer

- **`llms.txt`:** generated by the plugin. It holds a project summary, then links to the runbooks first and the guides second. A short custom preamble names the source of truth: "runbooks are executable; guides explain".
- **Runbooks** (`/agents/runbook-tier-N.md`) are plain Markdown. Each step has a fixed shape:
  - **Precondition:** a command and its expected output, e.g. `adb get-state` → `device`; `adb shell getprop ro.product.device` → `karat`.
  - **Action:** a single command.
  - **Verify:** a command and expected output, e.g. `adb shell cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME` → last line `dev.glasslauncher/...`.
  - **On failure:** a rollback command and "stop and ask the user".
  - **Needs user:** a marker for physical actions (re-plugging USB, pressing remote buttons) and for any write the user must approve.
- The runbooks reuse `rom/tools/smoke.sh` and `device-checks.sh` rather than inlining long checks, so they are tested code.
- The runbooks have safety rules at the top:
  - never flash lk, preloader, tz or vbmeta;
  - always back up before writing;
  - one stick per session;
  - no serials or home paths in reports.
- **Runbook test:** CI checks that every runbook command block parses (`bash -n`) and that every referenced script exists. Before each release, a Claude Code session runs one runbook end to end on a stick and records the transcript summary in the release notes.

## Troubleshooting and quirks: seed content (from our own notes)

- Alexa crashes on hold ("windowTemplateId cannot be null"). Cause: `com.amazon.aria` was removed. Fix: `cmd package install-existing com.amazon.aria`.
- The remote unpairs after reboot. Cause: Fire's AutoPairService re-pair at 60 s. Fix: the keepalive (part of Glass Pro). Pairing from scratch: reboot, wait ~60 s, hold Home 10 s.
- Two Glass instances start. Cause: the launcher was started with `am start -n`. Glass Pro starts it via the HOME intent.
- Bootloop after installing a module. Fix: `adb wait-for-device shell magisk --remove-modules`; otherwise go to TWRP and delete the module dir. The stick has no volume keys for safe mode.
- Getting to TWRP: `adb reboot recovery`. If Android is dead, use the preloader handshake with the USB re-plug steps (spec section 12).
- Factory reset behaviour on Glass OS (filled in after plan Task 21).
- Prime Video and Alexa share one Amazon account (FAQ, from account-center.md).
- A privileged app missing its allowlist entry stops boot (`ro.control_privapp_permissions=enforce`).

## Contributing guide: contents

- Repo layout.
- Prerequisites:
  - Homebrew: e2fsprogs, brotli, p7zip, bats-core;
  - aapt2;
  - Python 3, run with `-I`;
  - Node 22+ for the site.
- How to run tests (`bats tests/`, `pytest`).
- How to propose a package removal: evidence, lint, a 24 h disable test.
- Conventional Commits.
- `leak-check` before every PR. Amazon binaries and decompiled code never go in git; summaries only.
- How to add support for another OTA build or device: allowlist sha, partition sizes, D-checks.
